# AGENTS.md — Threat Information Service

## Назначение

Реализовать на Go HTTP REST API для обмена информацией о файловых угрозах в соответствии с OpenAPI 3.0.0 из задания. На текущем этапе реализовать **только обязательную часть**. Не добавлять Docker, СУБД, авторизацию, rate limiting, TLS, кодогенерацию и обширный набор тестов без отдельного запроса пользователя.

## Порядок работы

1. Изучить существующие файлы репозитория до внесения изменений.
2. Если проект пустой, создать Go-модуль и предложенную ниже структуру.
3. Работать последовательно: модель и OpenAPI → хранилище → сервис → HTTP-обработчики → запуск и проверка.
4. Не менять публичный API без необходимости. Отступления от исходной спецификации должны быть явно объяснены.
5. После каждого законченного этапа кратко перечислять изменённые файлы, принятые решения и способ проверки.
6. Не добавлять необязательные функции «на будущее»; писать простой, читаемый Go-код.

## Стек и ограничения

- Go 1.22 или новее.
- Для HTTP использовать стандартную библиотеку `net/http` (паттерны маршрутов Go 1.22+).
- Для JSON использовать `encoding/json`.
- Хранение — в памяти процесса: `map[string]Threat` с `sync.RWMutex`.
- Использовать разделение на domain / repository / service / transport/http.
- Добавление внешних зависимостей должно быть обосновано; на первом этапе они не требуются.

## Модель угрозы

Сохранить исходные поля:
- `md5` — строка, обязательная при создании, 32 шестнадцатеричных символа, уникальный ключ;
- `name` — строка, обязательная при создании и обновлении, непустая после `strings.TrimSpace`.

Добавить осмысленные поля:
- `type` — необязательное enum: `trojan`, `worm`, `ransomware`, `backdoor`, `other`;
- `severity` — необязательное enum: `low`, `medium`, `high`, `critical`;
- `description` — необязательная строка;
- `detected_at` — необязательная дата-время в формате RFC3339 (`date-time` в OpenAPI).

Не заполнять отсутствующие сведения выдуманными значениями. Если поле не задано, сохранять его отсутствие в JSON там, где это уместно (`omitempty`). Документировать ограничения и схемы в `openapi.yaml`. Определить отдельные типы запросов на создание и обновление, а также ответа. Для PUT `md5` берётся только из пути и не может изменяться.

## Требуемые HTTP-операции

### POST /info

Принимает JSON с `md5`, `name` и необязательными дополнительными полями. Создаёт новую запись.
- `201 Created` — ответ JSON со всей сохранённой угрозой;
- `400 Bad Request` — невалидный JSON или поля;
- `409 Conflict` — MD5 уже существует;
- `500 Internal Server Error` — непредвиденная ошибка.

### GET /info/{md5}

- `200 OK` — полный JSON угрозы;
- `400 Bad Request` — MD5 не соответствует шаблону `^[a-fA-F0-9]{32}$`;
- `404 Not Found` — запись отсутствует;
- `500 Internal Server Error` — непредвиденная ошибка.

### PUT /info/{md5}

Заменяет изменяемую информацию существующей угрозы. Требует `name`; остальные дополнительные поля опциональны. Отсутствующие необязательные поля при PUT очищаются (полная замена изменяемых полей), а `md5` сохраняется из пути.
- `200 OK` — обновлённая угроза;
- `400 Bad Request` — ошибка в пути, JSON или полях;
- `404 Not Found` — запись отсутствует;
- `500 Internal Server Error` — непредвиденная ошибка.

Все ответы, включая ошибки, имеют `Content-Type: application/json`. Ошибки возвращать в формате `{"message":"...","details":"..."}`. Не раскрывать внутренние детали сервера в ответах 500.

## Правила реализации

- Нормализовать MD5 в нижний регистр для хранения, поиска и проверки уникальности: два регистра одного хеша должны считаться одинаковым ключом.
- Валидировать MD5 именно как 32 ASCII-символа из `[0-9a-fA-F]`.
- Отклонять пустые имена и неизвестные значения enum; проверять дату как RFC3339.
- Отклонять JSON с неправильными типами полей, лишним содержимым после JSON-объекта и, предпочтительно, неизвестными полями (`DisallowUnknownFields`).
- Не допускать гонок данных: `sync.RWMutex` вокруг операций с map.
- Уникальность проверять атомарно внутри операции создания в репозитории.
- Ошибки `not found`, `already exists`, `validation` различать на уровне сервиса и корректно сопоставлять HTTP-статусам.
- Не использовать глобальное изменяемое хранилище; передавать зависимости конструкторам.
- Предусмотреть корректное завершение HTTP-сервера при SIGINT/SIGTERM, если это не усложняет реализацию.

## Критерии готовности обязательной части

1. `go run ./cmd/server` запускает сервис (по умолчанию порт 8080).
2. `POST /info` создаёт угрозу, `GET /info/{md5}` её возвращает, `PUT /info/{md5}` обновляет.
3. Возвращаются указанные в OpenAPI статусы 200/201/400/404/409; неожиданные ошибки обрабатываются как 500.
4. Запросы и ответы JSON соответствуют обновлённому `openapi.yaml`.
5. Дубликаты MD5 корректно выявляются независимо от регистра; чтение/запись потокобезопасны.
6. `go build ./...` и `go vet ./...` выполняются без ошибок.
7. `README.md` содержит команды запуска и несколько примеров `curl`, а также явно поясняет, что данные хранятся только в памяти и исчезнут при перезапуске.
