# Threat Information Service

[![Go](https://img.shields.io/badge/Go-1.26.2-00ADD8?logo=go&logoColor=white)](go.mod)[![API](https://img.shields.io/badge/API-REST-2563EB)](#api)[![OpenAPI](https://img.shields.io/badge/OpenAPI-3.0.0-6BA539?logo=openapiinitiative&logoColor=white)](openapi.yaml)[![Storage](https://img.shields.io/badge/Storage-In--memory-F59E0B)](#структура)

HTTP REST API для обмена информацией о файловых угрозах на Go.
Контракт описан в [openapi.yaml](openapi.yaml), исходное задание — в [task.md](task.md).
Для HTTP, JSON и тестов используется стандартная библиотека Go.
Единственная внешняя зависимость — `github.com/joho/godotenv` для чтения `.env`:
она обрабатывает формат файла без собственного парсера конфигурации.

**Данные хранятся в памяти процесса и полностью исчезают после остановки или
перезапуска сервера.** Разные экземпляры сервера не разделяют данные.

## Запуск

Требуется Go 1.26.2 или новее, согласно `go.mod`.
Все команды выполняются из корня проекта.

```bash
go run ./cmd/server
```

По умолчанию сервер слушает `:8080` на всех сетевых интерфейсах.
Адрес можно изменить переменной окружения:

```bash
HTTP_ADDR=127.0.0.1:9090 go run ./cmd/server
```

Для настройки через файл скопируйте `.env.example` в `.env`, задайте нужный
`HTTP_ADDR`. Сервер автоматически прочитает `.env` из текущего рабочего каталога:

```bash
cp .env.example .env
# Отредактируйте .env перед запуском.
go run ./cmd/server
```

Уже заданные переменные окружения имеют приоритет над `.env`.
Если ранее выполняли `source .env`, используйте `unset HTTP_ADDR`, чтобы снова
применялось значение из файла. Файл `.env` необязателен; если `HTTP_ADDR` не задан
или пуст, используется `:8080`. Повреждённый или недоступный `.env`, ошибочный
адрес и занятый порт приводят к завершению с ошибкой. `.env` исключён из Git.

Остановка — Ctrl+C (SIGINT) или SIGTERM. Сервер прекращает принимать новые
соединения и даёт текущим запросам до пяти секунд на завершение, затем
принудительно закрывает оставшиеся соединения.

## API

| Метод и путь | Назначение | Статусы |
| --- | --- | --- |
| `POST /info` | Создать угрозу | 201, 400, 409, 500 |
| `GET /info/{md5}` | Получить угрозу | 200, 400, 404, 500 |
| `PUT /info/{md5}` | Заменить изменяемые поля угрозы | 200, 400, 404, 500 |

Поля запроса:

| Поле | Правило |
| --- | --- |
| `md5` | Обязательно для POST: 32 ASCII-символа из `[0-9a-fA-F]`. В PUT берётся только из пути |
| `name` | Обязательно: строка, непустая после `strings.TrimSpace` |
| `type` | Обязательно: `trojan`, `worm`, `ransomware`, `backdoor`, `other` |
| `severity` | Необязательно: `low`, `medium`, `high`, `critical` |
| `description` | Необязательная строка; пустая строка разрешена |
| `detected_at` | Необязательная строка с датой и временем RFC3339 |

MD5 сохраняется и возвращается в нижнем регистре. Поиск и проверка дубликатов
не зависят от регистра. Сервер принимает готовый MD5, файлы не загружает и хеш
самостоятельно не вычисляет.

PUT полностью заменяет изменяемые поля существующей записи: пропущенные
`severity`, `description`, `detected_at` очищаются. MD5 в теле PUT запрещён.
Несуществующая запись при PUT не создаётся.

Неизвестные поля, включая имена с неверным регистром, неверные JSON-типы,
явные `null`, пустые enum и даты, а также дополнительные данные после объекта
отклоняются с 400. Пустые необязательные поля не включаются в ответ.

Ответы API имеют `Content-Type: application/json`. Формат ошибки:

```json
{"message":"Угроза не найдена","details":"Запись с указанным MD5 отсутствует"}
```

Неизвестный маршрут возвращает 404, неподдерживаемый метод — 405 с заголовком
`Allow`. Пути с повторными слешами или сегментами `.` / `..` возвращают 400
вместо автоматического перенаправления. В ответах 500 внутренние ошибки не
раскрываются, подробности записываются в серверный лог.

## Примеры curl

Запустите сервер и выполните команды в другом терминале. Если порт изменён,
укажите его в `API_URL`.

```bash
API_URL=http://127.0.0.1:8080
```

Создание — 201:

```bash
curl -i -X POST "$API_URL/info" \
  -H 'Content-Type: application/json' \
  -d '{
    "md5": "D41D8CD98F00B204E9800998ECF8427E",
    "name": "Trojan.Win32.Generic",
    "type": "trojan",
    "severity": "high",
    "description": "Учебная запись",
    "detected_at": "2026-10-24T12:00:00Z"
  }'
```

Чтение — 200:

```bash
curl -i "$API_URL/info/d41d8cd98f00b204e9800998ecf8427e"
```

Полная замена — 200. Дополнительные поля прежней записи будут очищены:

```bash
curl -i -X PUT "$API_URL/info/d41d8cd98f00b204e9800998ecf8427e" \
  -H 'Content-Type: application/json' \
  -d '{"name":"Updated threat","type":"worm"}'
```

Повторное создание того же MD5 — 409:

```bash
curl -i -X POST "$API_URL/info" \
  -H 'Content-Type: application/json' \
  -d '{"md5":"d41d8cd98f00b204e9800998ecf8427e","name":"Duplicate","type":"other"}'
```

Некорректный MD5 — 400:

```bash
curl -i "$API_URL/info/invalid"
```

После перезапуска чтение ранее созданной записи вернёт 404.

## Проверки

```bash
go build ./...
go vet ./...
go test ./...
go test -race ./...
```

Юнит-тесты находятся рядом с кодом в `internal`, интеграционные —
в `tests/integration`:

```bash
go test -v ./internal/...
go test -v ./cmd/server
go test -v ./tests/integration
```

Интеграционные тесты сами запускают HTTP-сервер на свободном локальном порту
и используют настоящие сервис и хранилище. Запускать приложение вручную не нужно.

## Структура

```text
cmd/server/              сборка зависимостей, запуск и остановка
internal/domain/         модель угрозы и enum
internal/repository/     хранилище map с sync.RWMutex
internal/service/        валидация, нормализация MD5 и операции
internal/transport/http/ маршруты, JSON-запросы и ответы
tests/integration/       интеграционные HTTP-тесты
```

По согласованному уточнению исходного задания поле `type` обязательно при
создании и обновлении; это отражено в OpenAPI. `severity` остаётся необязательным.
База данных, Docker, авторизация, TLS и rate limiting в текущую реализацию
не входят.
